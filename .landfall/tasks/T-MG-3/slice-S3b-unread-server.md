## Problem
S3 added "Mark unread" on a message (src/http/ui/js/view-chat.js markUnreadFrom, ~line 1044): it paints the local state and POSTs /api/conversations/:id/read with messageId = id - 1. The server's markRead (src/core/unread.ts:125-150) clamps with `MAX(last_read_message_id, ?)`, so the marker never moves back: after F5 the conversation is read again. A "Mark unread" that silently reverts misleads the human.

## Fix (files: src/core/unread.ts, src/http/routes/conversations.ts, src/http/ui/js/view-chat.js markUnreadFrom ONLY (one line: the endpoint), test/core-mark-unread.test.ts, and the MCP/CLI only if you decide agents need it - say so in the report, default: not needed)
