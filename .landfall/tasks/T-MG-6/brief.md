2. B-MG-3 (blocking): src/core/wake.ts ~193: disabling an actor leaves its wake webhook active; new private content is still sent. Fix: isWakeable and the dispatch path check actors.disabled_at (and a revoked/expired token if wake is token-bound) immediately before sending. Test with the injected deliverer used in existing wake tests: setWake(B), disable B, post a mention of B -> zero deliveries.

B-MG-19 (minor): wake body has no expiry/nonce -> add a signed `exp` (now + 300 s) and a random nonce to the signed payload and document both for receivers (the docs live in AgentTalks.md: do NOT edit it, list the sentence to add in your report); isBlockedIp misses NAT64 64:ff9b::/96 (and 64:ff9b:1::/48) and 6to4 2002::/16 -> block them. 4. B-MG-5 (blocking) + B-MG-52: src/core/webauthn.ts ~286: a zero counter resets clone detection. Fix: if stored sign_count > 0 or received > 0, require received > stored, else reject; never lower the stored value; the always-zero authenticator (both 0) stays allowed. Test: counts 5 -> 0 rejected, 5 -> 5 rejected, 5 -> 6 ok, 0 -> 0 ok.
5. B-MG-8 (blocking): POST /api/actors (src/http/routes/auth.ts ~325) uses requireAdmin, which lets an AGENT admin create a HUMAN account. Fix: the same human-admin guard as /api/admin (requireHumanAdmin). Test: agent with isAdmin=true -> 403; human admin -> 201.
6. B-MG-44 (minor, Medium): login rate limit keyed by IP only and cleared by any successful login. Fix: count failures per IP+handle and per handle (in addition to per IP), clear only the IP+handle key on success. Test: 8 failed guesses on victim interleaved with successful logins of the attacker's own account from the same IP -> the 9th guess on the victim gets 429.
7. B-MG-45 (minor, Medium): POST /api/logout only expires the cookie client-side. Fix: invalidate server-side (the instance already has a session epoch mechanism - session_epoch - bump it for this session/actor, or store a per-session id and revoke it; choose the one that does not log the human out of OTHER devices unless the existing epoch is per-actor - say which in the report) and require CSRF on logout. Test: after logout, GET /api/me with the pre-logout cookie -> 401.
8. B-MG-51 (minor): no security logging. Add a single structured log line (console.warn with a fixed prefix "security:" and JSON) for: failed login, rate-limit hit, token minted, token revoked, invite minted, actor disabled/enabled, admin action denied (403). Never log a secret (password, token, cookie, invite code). Test: capture console output in one test and assert a failed login produces exactly one "security:" line with no password in it.
