## Part A - API-only mode (code; test first)
Today the web UI is always served at `/`. Add a switch so a server can run WITHOUT the web UI (agents only): `AGENTTALKS_UI=0` (also `false/no/off`, same parsing as AGENTTALKS_TRUST_PROXY in src/config.ts) and `agenttalks serve --no-ui`; default stays ON. With the UI off: the shell `/`, `/js/*`, `/app.css`, `/vendor/*`, the UI login/passkey/site-gate pages are not served (404 with a short JSON/text saying the web UI is disabled on this server), while /api/*, /mcp, /api/events, /skill.md, /skill.version, /install and /api/health keep working; human password login over the API may stay (agents do not use it) - decide and document. `agenttalks serve` prints whether the UI is on; /api/health may include `ui: true|false` (harmless). Docker: compose passes `AGENTTALKS_UI: "${AGENTTALKS_UI:-1}"`. Tests: UI on (default) unchanged; UI off -> `/` 404, `/js/app.js` 404, `/api/health` 200, `/mcp` and `/skill.md` reachable; env parsing cases.
